# Тестирование практической работы №6

Перед тестированием должна быть запущена PostgreSQL, создана `productdb`, выполнен `db_init.sql`, а приложение должно быть развернуто в Tomcat.

Администратор по умолчанию:

- Login: `admin`
- Password: `admin123`

## Тест 1. Регистрация User

1. Открыть `/productapp/register`.
2. Ввести логин `student`.
3. Ввести пароль `student123`.
4. Нажать `Зарегистрироваться`.

Ожидаемый результат: сообщение об успешной регистрации и переход на страницу входа.

## Тест 2. Проверка регистрации с коротким паролем

1. Открыть регистрацию.
2. Ввести логин `abc`.
3. Ввести пароль `123`.
4. Отправить форму.

Ожидаемый результат: диагностическое сообщение о том, что пароль должен содержать минимум 6 символов. Пользователь не создается.

## Тест 3. Проверка повторного логина

1. Зарегистрировать пользователя `student`.
2. Повторно открыть регистрацию.
3. Ввести `student` и другой пароль.

Ожидаемый результат: сообщение `Пользователь с таким именем уже существует`.

## Тест 4. Вход обычного пользователя

1. Войти как `student`.
2. Открыть список продуктов.
3. Открыть поиск по названию.
4. Открыть поиск по цене.

Ожидаемый результат: страницы просмотра и поиска доступны. На странице отображается приветствие с логином вошедшего пользователя.

## Тест 5. Ограничение User на CRUD

Будучи авторизованным как `student`, вручную открыть:

```text
/productapp/products/add
/productapp/products/edit/1
/productapp/products/delete/1
```

Ожидаемый результат: Spring Security запрещает доступ и показывает страницу `Доступ запрещен`.

## Тест 6. Вход администратора

1. Выполнить logout.
2. Войти:
   - Login: `admin`
   - Password: `admin123`

Ожидаемый результат: успешный вход. В представлении отображаются элементы, предназначенные для Admin.

## Тест 7. Добавление продукта

Под Admin открыть добавление продукта и заполнить:

```text
Название: Тестовый продукт
Категория: Тест
Производитель: Тестовый производитель
Цена: 100
Калории: 200
```

Ожидаемый результат: продукт появляется в общем списке.

## Тест 8. Проверка валидации продукта

В форме добавления указать, например:

```text
Название: A
Цена: 0
Калории: -1
```

Ожидаемый результат: форма не отправляется успешно и показывает диагностические сообщения валидации.

## Тест 9. Редактирование

Под Admin открыть редактирование добавленного продукта, изменить цену, сохранить.

Ожидаемый результат: измененные данные отображаются в списке.

## Тест 10. Удаление

Под Admin открыть удаление тестового продукта и подтвердить.

Ожидаемый результат: запись исчезает из списка.

## Тест 11. Поиск

Проверить:

- поиск по названию `Яблоки`;
- поиск по цене `100`.

Ожидаемый результат: выводятся записи, удовлетворяющие соответствующему критерию.

## Тест 12. Logout

1. Нажать `Выйти из системы`.
2. Попробовать открыть страницу администратора.

Ожидаемый результат: сессия завершена, защищенные операции требуют повторной авторизации.
